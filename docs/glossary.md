# 术语释义

界面上很多标签（吉神凶煞、建除、二十八宿、月相……）只有名字，看不懂。这一层给它们配一句白话释义和一句公版原文，鼠标悬停或键盘聚焦时出浮层，点击展开带出处的详情。

## 交互

| 操作                             | 结果                                     |
| -------------------------------- | ---------------------------------------- |
| 鼠标悬停 / `Tab` 聚焦            | 浮层：白话一句 + 原文定义句              |
| 点击 / `Enter`                   | 详情：再加出处，可停留阅读               |
| 再次点击 / `Esc` / 点击别处      | 关闭                                     |
| 设置 → 显示 → 术语说明（默认开） | 关掉后所有术语退回纯文本，无按钮、无监听 |

浮层渲染在 `document.body` 的 portal 里（`position: fixed`），因此不受面板 `overflow` 与层叠上下文影响；靠近视口下边缘会翻到上方，左右越界会夹在视口内。全应用同时只有一个浮层。

视口内没有释义的标签**渲染成纯文本**，不会变成点了没反应的按钮。

## 数据从哪来

### 主源：《钦定协纪辨方书》四库全书本

[维基文库](<https://zh.wikisource.org/zh-hant/%E6%AC%BD%E5%AE%9A%E5%8D%94%E7%B4%80%E8%BE%A8%E6%96%B9%E6%9B%B8_(%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC)>) 收录全文，页面明确标注公有领域（"作者逝世已经超过100年，且作品於1931年1月1日之前出版"）。

全书三十六卷，**卷三–卷八是「义例」——神煞释义就在这六卷**。实测规则：

```
《协纪辨方书》卷一–卷八  →  151 个日神名命中 147 个
```

### 为什么不用 cnlunar 的 `book.json`

它虽然是 MIT 仓库，但 `book.json` 是《协纪辨方书》**年神/方位神**部分的摘录，收集的是岁德、太岁、大将军、黄幡豹尾这一套，**不是每日神煞**；而且每条 1000–5000 字，当浮层文案没法用。它的今译部分来源也存疑（有 OCR 错字，疑似取自现代排印本），而 MIT 只覆盖代码，不覆盖这类文本。

## 别把三套「神煞」混在一起

名字大量重叠，含义与推法完全不同。贴错比不贴更糟。

| 系统         | 代表术语                           | 推法              | 本应用里对应         |
| ------------ | ---------------------------------- | ----------------- | -------------------- |
| **择日神煞** | 天恩、母仓、月德、青龙、劫煞、五虚 | 月支 + 日干支查表 | 日详情的「吉神凶煞」 |
| **命理神煞** | 天乙贵人、桃花、驿马、羊刃、文昌   | 命主四柱          | 八字排盘页           |
| **方位神煞** | 太岁、岁破、大将军、黄幡、豹尾     | 年支定方位        | 未展示               |

## 依据分档

每个家族声明一个 `basis`，决定 `quote` 是否必需：

| basis    | 含义                             | 要求                                        |
| -------- | -------------------------------- | ------------------------------------------- |
| `xieji`  | 《协纪辨方书》义例，有原文定义句 | 必须有 `quote` + `source` + `fixture`       |
| `common` | 天文/历法常识，不存在异说        | 必须有 `rationale` 说明为什么不需要典籍依据 |

**没有可靠出处的一律不写。** 与其编一句"通行说法"，不如让那个标签不出浮层。

### 已知缺口

`god` 缺 46 个，`star28` 缺 5 个（昴、毕、觜、井、鬼）。完整名单在 `tests/glossary-contract.test.ts` 的 `KNOWN_GAPS`，是显式断言——**新增覆盖时那条测试会失败**，逼着把清单一起改掉。

`god` 的缺口分三类：

1. **《协纪辨方书》本就删去或只在义例目录列名、正文无释义**（鬼哭、七符、大退、岁薄、逐阵……）。卷首奏议明确列了一批"應刪去"的俗名，后世通书又捡了回来——这是权威源与通书的真实分歧。
2. **只在他条之下作别名带过**（时德附在四相条、解除附在解神条……），单独摘出来会断章取义。
3. **定义夹在成组的阴阳诸神长文里**（阴阳交破、单阴、纯阳……），逐条切分不可靠。

另外 `nineStar`（九星）、`sixStar`（六曜）、`minorRen`（小六壬）**整族没有收录**：它们只有民间通行说法，找不到可逐字引用的公版权威依据。

## 引文怎么校验

`tests/glossary-contract.test.ts` 断言每条 `quote` 都出现在 `tests/fixtures/` 的原文里，**比较时忽略空白与标点**：

- 四库本原无句读，标点是后人补的，所以要允许补标点；
- 但**文字一个字都不能多、不能少、不能改**——这条挡的是编造引文。

拿不到可校验的引文，就不该收录。

### 四库异体字的坑

原文用四库本的异体写法，而 MediaWiki 的简繁转换**不处理**它们。漏掉归一化，日神覆盖率会从 147 掉到 141——「月德合 / 天德合 / 阴德 / 阳德 / 时德」全部匹配不上，因为原文写的是 `月徳合`（`徳` U+5FB3，不是 `德` U+5FB7）。

异体字表在 `scripts/glossary/variants.mjs`。另一个同类问题：**引擎的 `玄武` 在四库本里写作 `元武`**（避康熙玄烨讳），所以词条的 key 必须是引擎名 `元武`，引文里也保留 `元武`。

## 怎么加一条词条

1. 跑 `node scripts/glossary/extract-quotes.mjs`，看这个术语有没有候选定义句；
2. **人工核对上下文**——抽取器只能保证"这句话在原文里"，不能保证"这句话是这个词的正确定义"。单字名（建、角）尤其容易误命中，`青龙`/`金匮`/`福德`/`天医` 在《协纪辨方书》里既指黄历神煞又指纳甲六神和大游年卦；
3. 把引文与白话写进 `src/core/glossary/texts/<家族>.ts`；
4. 如果它是原本的缺口，从 `KNOWN_GAPS` 里删掉；
5. `npm test` —— 引文校验和缺口断言会替你复核。

## 脚本

| 脚本                                       | 用途                                                                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `node scripts/glossary/fetch-source.mjs`   | 从维基文库抓公版原文到 `tests/fixtures/`，已存在则跳过；`--force` 强制重抓。需要网络，**CI 不跑它**                       |
| `node scripts/glossary/extract-quotes.mjs` | 从 fixture 里抽候选定义句，输出 `名称 / 卷 / 层级 / 引文`。`T1` 是可信的 `X者…也` 句型，`T2` 是宽松句型，**必须人工核对** |

## 数据放在哪

```
src/core/glossary/
├─ types.ts            契约
├─ index.ts            GLOSSARY / GLOSSARY_FAMILIES / lookupTerm
└─ texts/              纯数据，按家族分文件
tests/fixtures/xieji-bianfangshu/   《协纪辨方书》卷一–卷八（公有领域）
```

放 `src/core` 而不是渲染层，是因为它是"关于历法术语的知识"，与界面无关；也因此能写出「每个 key 都必须在引擎的表里」这条契约测试。

`src/core/glossary/**` **不 import tyme4ts**——它保持纯数据，引擎的权威名单由测试自己引入并交叉校验。

fixture 放 `tests/` 而不是 `src/`：运行时永不 import，`electron-builder.yml` 已排除 `tests/**`，不会进 asar；同时它是引文校验的输入。
