# 术语释义

界面上很多标签（吉神凶煞、建除、二十八宿、月相……）只有名字，看不懂。这一层给它们配一句白话释义和一句公版原文，鼠标悬停或键盘聚焦时出浮层，点击展开带出处的详情。

**找不到释义的标签也出浮层**——浮层老实说明缺什么，并且在原文里确实提到过的时候，把位置指给读者自己去查。宁可说"我不知道"，也不让标签悬停时毫无反应，更不编造出处。

## 交互

| 标签状态               | 悬停 / `Tab` 聚焦                   | 点击 / `Enter`               |
| ---------------------- | ----------------------------------- | ---------------------------- |
| 有释义                 | 白话一句 + 原文定义句               | 再加出处                     |
| 只有缺口说明           | 「暂无释义」+ 为什么缺 + 能查到哪里 | 同上（缺口通常本来就带出处） |
| 设置关掉了「术语说明」 | 全部退回纯文本，无按钮、无监听      | —                            |

再次点击、`Esc`、点击别处都会关闭。

浮层渲染在 `document.body` 的 portal 里（`position: fixed`），因此不受面板 `overflow` 与层叠上下文影响；靠近视口下边缘会翻到上方，左右越界会夹在视口内。全应用同时只有一个浮层，缺口浮层底色略深以示区别。

## 数据从哪来

### 主源：《钦定协纪辨方书》四库全书本

[维基文库](<https://zh.wikisource.org/zh-hant/%E6%AC%BD%E5%AE%9A%E5%8D%94%E7%B4%80%E8%BE%A8%E6%96%B9%E6%9B%B8_(%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC)>) 收录全文，页面明确标注公有领域（"作者逝世已经超过100年，且作品於1931年1月1日之前出版"）。

全书三十六卷，**卷三–卷八是「义例」——神煞释义就在这六卷**。

### 为什么不用 cnlunar 的 `book.json`

它虽然是 MIT 仓库，但 `book.json` 是《协纪辨方书》**年神/方位神**部分的摘录，收集的是岁德、太岁、大将军、黄幡豹尾这一套，**不是每日神煞**；而且每条 1000–5000 字，当浮层文案没法用。它的今译部分来源也存疑（有 OCR 错字，疑似取自现代排印本），而 MIT 只覆盖代码，不覆盖这类文本。

## 别把三套「神煞」混在一起

名字大量重叠，含义与推法完全不同。贴错比不贴更糟。

| 系统         | 代表术语                           | 推法              | 本应用里对应         |
| ------------ | ---------------------------------- | ----------------- | -------------------- |
| **择日神煞** | 天恩、母仓、月德、青龙、劫煞、五虚 | 月支 + 日干支查表 | 日详情的「吉神凶煞」 |
| **命理神煞** | 天乙贵人、桃花、驿马、羊刃、文昌   | 命主四柱          | 八字排盘页           |
| **方位神煞** | 太岁、岁破、大将军、黄幡、豹尾     | 年支定方位        | 未展示               |

## 依据分档

每个家族声明一个 `basis`，决定 `quote` 是否必需、详情里怎么标出处：

| basis      | 含义                             | 要求                                     |
| ---------- | -------------------------------- | ---------------------------------------- |
| `xieji`    | 《协纪辨方书》义例，有原文定义句 | 必须有 `quote` + `source` + `fixture`    |
| `common`   | 天文/历法常识，不存在异说        | 必须有 `rationale`                       |
| `authored` | 本应用撰写的通俗释义             | 必须有 `rationale`；详情里标明是自行撰写 |
| `none`     | 整族拿不到依据，全部是缺口       | 必须有 `rationale`；`entries` 必须为空   |

`authored` 这一档存在的原因：**宜忌条目的词义在古籍里根本没有**。查过《协纪辨方书》卷十「宜忌」与卷十一「用事」，它们只规定哪个神宜/忌哪些事（原文就是「…嫁娶、纳采、问名、般移、解除…」这样的清单），从不解释词义。既然释义是自己写的，就得标明是自己写的，不能混进有出处的那一档。

**拿不到可靠出处的，不写释义。** 但它仍然会出浮层，只是浮层说的是「暂无释义」和为什么——见下面的缺口。

| `term`       | 节气标签、年视图节气表 | common   |
| `taboo`      | 日详情「宜」「忌」     | authored |
| `nineStar`   | 日详情「九星」         | none     |
| `sixStar`    | 日详情「六曜」         | none     |

**这里刻意不写每个家族覆盖了多少条。** 那是随词条增删而变的派生数据，抄进文档只会过期，而且没有任何东西会因此失败。真正的保证由契约测试给：**释义 + 缺口 = 引擎全部名单**，一个不多一个不少——任何名字被悄悄漏掉（悬停无反应），或写错字写成引擎不认识的名字，都会让 `npm test` 失败。要看具体数字就跑测试。

### 缺口是怎么说的

`reason` 只有五种措辞，不逐条编故事：

| 措辞                                                  | 用在                                                                   |
| ----------------------------------------------------- | ---------------------------------------------------------------------- |
| 《协纪辨方书》提到过，但没有单独解释它的含义          | 卷三–卷八里出现过，但那是别名带过或夹在成组长文里                      |
| 《协纪辨方书》没有收录它，也没找到其他可靠的古籍解释  | 连原文都没出现过                                                       |
| 《协纪辨方书》引《史记·律书》解释二十八宿，但没讲到它 | 昴、毕、觜、井、鬼                                                     |
| 这是民间流传的说法，古籍里没有解释                    | 九星、六曜、小六壬整族                                                 |
| 这个名目比较生僻，我们暂时不确定它的准确含义          | 宜忌里的「归岫」（这一族是我们自己写的，所以是"不确定"而非"古籍没有"） |

第一、二类的区别值得留意：**出现在原文里**和**有可引用的释义**是两回事。卷三–卷八提到某个名字，往往是在别的条目下带一笔（时德在四相条、解除在解神条），或者在阴阳诸神的长文里，逐条切出来就会断章取义。这时候 `source` 指向它出现的那一卷，读者可以自己去查——但**不冒充释义**。

`god` 的缺口里相当一部分是《协纪辨方书》**刻意删去**的：卷首奏议明确列了一批"應刪去"的俗名，后世通书又捡了回来。这是权威源与通书的真实分歧，不是我们漏了。

## 多语言

现在是**单语言（简体）**，`lookupTerm(family, name)` 没有语言参数，文案是硬编码的简体字符串。

要做繁体版需要先重构，成本如下：

1. `tests/fixtures/.../{zh-Hans,zh-Hant}/` + `fetch-source.mjs` 支持 `--variant`。**引文校验必须逐字对得上**，而现有 fixture 是抓取时用 `variant=zh-hans` 转过的，所以繁体版得把八卷重抓一遍。
2. `src/core/glossary/texts/{zh-Hans,zh-Hant}/`，`lookupTerm(locale, family, name)`，`GLOSSARY: Record<Locale, …>`。
3. `AppSettings.locale` + 设置项，契约测试按语言各跑一遍。

**繁体不能靠机械转换**：术语里有一简对多繁（「历」在「万年历」应作「曆」，在「日历」才是「歷」；复/復/複、发/發/髮同理），转错术语比不转更糟。所以全部词条与缺口说明都得真写一遍繁体，这才是主要成本——第 1、2 步是机械的。

## 引文怎么校验

`tests/glossary-contract.test.ts` 断言每条 `quote` 都出现在 `tests/fixtures/` 的原文里，**比较时忽略空白与标点**：

- 四库本原无句读，标点是后人补的，所以要允许补标点；
- 但**文字一个字都不能多、不能少、不能改**——这条挡的是编造引文。

拿不到可校验的引文，就不该写释义。

### 四库异体字的坑

原文用四库本的异体写法，而 MediaWiki 的简繁转换**不处理**它们。漏掉归一化，「月德合 / 天德合 / 阴德 / 阳德 / 时德」这几个全部匹配不上，因为原文写的是 `月徳合`（`徳` U+5FB3，不是 `德` U+5FB7）。

异体字表在 `scripts/glossary/variants.mjs`。另一个同类问题：**引擎的 `玄武` 在四库本里写作 `元武`**（避康熙玄烨讳），所以词条的 key 必须是引擎名 `元武`，引文里也保留 `元武`。

## 怎么加一条词条

1. 跑 `node scripts/glossary/extract-quotes.mjs`，看这个术语有没有候选定义句；
2. **人工核对上下文**——抽取器只能保证"这句话在原文里"，不能保证"这句话是这个词的正确定义"。单字名（建、角）尤其容易误命中；`青龙`/`金匮`/`福德`/`天医`/`生气` 在《协纪辨方书》里既指黄历神煞，也指纳甲六神和大游年卦；
3. 把引文与白话写进 `src/core/glossary/texts/<家族>.ts`；
4. 把它的名字从 `texts/gaps.ts` 里删掉（同一个名字不能既是释义又是缺口，测试会拦）；
5. `npm test` —— 引文校验与覆盖断言会替你复核。

## 脚本

| 脚本                                       | 用途                                                                                                                      |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `node scripts/glossary/fetch-source.mjs`   | 从维基文库抓公版原文到 `tests/fixtures/`，已存在则跳过；`--force` 强制重抓。需要网络，只在开发机上手动跑                  |
| `node scripts/glossary/extract-quotes.mjs` | 从 fixture 里抽候选定义句，输出 `名称 / 卷 / 层级 / 引文`。`T1` 是可信的 `X者…也` 句型，`T2` 是宽松句型，**必须人工核对** |

## 数据放在哪

```
src/core/glossary/
├─ types.ts            契约
├─ index.ts            GLOSSARY / GLOSSARY_FAMILIES / lookupTerm
└─ texts/              纯数据，按家族分文件
tests/fixtures/xieji-bianfangshu/   《协纪辨方书》卷一–卷八（公有领域）
```

放 `src/core` 而不是渲染层，是因为它是"关于历法术语的知识"，与界面无关；也因此能写出「每个 key 都必须在引擎的表里」这条契约测试。

`src/core/glossary/**` **不 import tyme4ts**——它保持纯数据，引擎的权威名单由测试自己引入并交叉校验。

fixture 放 `tests/` 而不是 `src/`：运行时永不 import，`electron-builder.yml` 已排除 `tests/**`，不会进 asar；同时它是引文校验的输入。
