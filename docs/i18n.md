# 语言与文案

界面上所有文字都来自 `src/renderer/src/i18n/`。这一层目前只有简体中文，但骨架
是完整的：加一种语言只需要加一个目录、在 `Locale` 联合里加一个成员。

## 为什么自己写而不是用 i18n 库

需求只有三条：键的类型安全、切换语言后立刻生效、以及能被测试拦住"又写死中文了"。
现成的库（i18next、react-intl 等）都能做，但会引入一个运行时依赖、一套占位符语法，
以及一个需要额外配置的复数和日期管线——而本应用恰恰**不需要** `Intl`：

历法日期不是 `Date`，而是「农历 + 节气 + 干支」这类引擎产出的中文片段组合，
`Intl.DateTimeFormat` 无从表达。所以日期与数字的本地化是显式的模板转换
（见下面的"日期怎么办"），而不是交给 `Intl`。

## 目录结构

```
src/renderer/src/i18n/
├─ index.ts           公开入口（组件只从这里 import）
├─ types.ts           契约说明
├─ locale-context.ts  LocaleContext / useLocale / useMessages
├─ LocaleProvider.tsx 把当前语言写到 <html lang> 并提供 context
└─ messages/
   ├─ index.ts        CATALOGS 注册表 + getMessages
   └─ zh-Hans.ts      参考目录：键的唯一来源
```

`Messages` 的类型由 `zh-Hans` **推导**（`typeof zhHans`），不手写。好处是新增语言时
编译器会直接列出缺哪些键，不需要维护第二份键清单。

## 怎么用

```tsx
import { useMessages } from '@renderer/i18n'

export function Example(): ReactElement {
  const t = useMessages()
  return <button>{t.toolbar.settings}</button>
}
```

取字段，不调 `t('toolbar.settings')`：字符串键写错只有运行期才暴露，字段则由
TypeScript 检查，还能自动补全。

带参数的文案直接写成函数：

```ts
titleWithVersion: ({ version }: { version: string }): string => `万年历 v${version}`
```

用函数而不是 `{name}` 占位符，理由同上：占位符拼错是运行期错误。语序、量词、
复数的差异也因此能各写各的——中文的「共 3 天」和英文的「3 days」不必共享模板。

## 三条规矩

1. **组件里不写死中文。** 由 `tests/i18n-contract.test.ts` 守住：扫描渲染层源码里
   含汉字的**代码行**，与该文件在 `tests/fixtures/i18n-contract/cjk-baseline.json`
   里的基线比较，**只许减少**。
   **注释里的中文不算**——那是给读代码的人看的，本仓库的注释本来就写中文；把注释
   算进来会让「加一段中文注释」也失败，规则就会被人用加基线的方式绕过去。
2. **模块级常量不能存文案。** 它们在 import 时冻结，切换语言后不会更新。要按语言
   取文案，就在组件里 `useMemo(() => …, [t])` 派生。
3. **语言名不翻译。** `localeNames` 里放各语言的自称，否则切到英文界面后就找不到
   「繁體中文」这一项了。

## 迁移期间的基线

抽取已完成。渲染层代码里只剩 **2 行**含中文，且两行都**刻意不抽**：

| 位置                               | 内容                                       | 为什么不抽                                                                                                                          |
| ---------------------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| `components/term-tip-context.ts`   | `useTermTip 必须在 TermTipProvider 内使用` | 开发期的 `throw`，是写错了代码才会看到的提示，不是给用户看的文案                                                                    |
| `features/pillars/PillarsTool.tsx` | `tenStar === '日主'`                       | `日主` 是「十神」的一个取值，与其余十神名一样都是引擎给的汉字，属于**历法数据**而非界面文案；它是被当作值比较的，不是渲染出来的标签 |

基线机制保留着，用来挡住新增：

```bash
node scripts/i18n/cjk-scan.mjs            # 看看现在各文件多少行
node scripts/i18n/cjk-scan.mjs --update   # 抽完之后重建基线
```

`--update` 之后要在提交信息里说明为什么降低——基线是"还欠多少"的账本，
不是可以随手刷新的快照。扫描口径（逐行剥掉块注释与行注释、再数代码里的汉字；
跳过 `i18n/` 与测试目录）在 `scripts/i18n/cjk-scan.mjs` 与测试里各有一份，
改一处要改两处，测试里带一条扫描器自测防止两边漂移。

## 消息往哪儿说

同一条"这件事的结果"有两种放法，分界是**用户接下来要做什么**：

| 放法                                                 | 用在                             | 例子                               |
| ---------------------------------------------------- | -------------------------------- | ---------------------------------- |
| 右下角的短提示（`components/ToastProvider.tsx`）     | 说一次就该走的操作结果           | 搬好了、下载失败、这个改动没存下来 |
| 写在控件旁边的一行（`tool__error` / `setup__error`） | 用户接下来要在**同一处**改点东西 | 这个位置不能用：换一个空文件夹     |

理由很朴素：常驻段落会一直挂着，直到用户改下一项才消失——于是"有一次没存上"看起来像这个应用
的永久状态。反过来，一句会自己消失的理由也没法对着改：用户得记得三秒前那句话说了什么。分界写错
是看得见的（测试直接查消息出现在哪一层），见 `src/renderer/src/__tests__/app.test.tsx` 与
`features/setup/__tests__/setup-view.test.tsx`。

写这类文案时的三条：

1. **先想这句话的功能**：报告结果、指出下一步，还是请求一个决定？只报告结果会退化成
   "操作已完成"，只指出下一步会写成一段说明书。
2. **不复述文档。**"数据会被移动到新的位置，这个过程可能需要一些时间，请耐心等待"里没有
   一个字是用户不知道的；`已搬到 D:\万年历数据，正在重启` 才是那条消息。
3. **句末不加句号**——提示是给人扫的，不是给人读的段落；能给下一步就给：
   `有文件正被占用，关掉占用它的程序再删`。

## 骨架屏文案

`src/renderer/index.html` 里有一个**零脚本依赖**的首帧骨架屏：窗口出现的第一帧就是
"日历正在准备"的占位画面，React 挂载后由 `src/renderer/src/splash.ts` 淡出交接。
它的文案不能走 `useMessages()`——那时候 i18n 层还没起来——所以是**受契约约束的
副本**：

- 唯一真相仍是各语言目录的 `app.splash` / `app.splashFirstRun`；
- `index.html` 里每个语言一对 `data-locale` 文案节点 + 两条显示规则，由
  `tests/splash-contract.test.ts` 断言与目录**逐字一致**、语言集合与 `LOCALES`
  一一对应。加语言时漏配骨架，`npm test` 直接红；
- `cjk-scan.mjs` 只扫 `src/renderer/src/**/*.tsx?`，**不覆盖** `index.html`——
  这份副本由 splash 契约守护，而不是由硬编码中文基线守护，两套机制别混用；
- 骨架内联样式里的颜色字面量同样被该测试钉为 `tokens.css` 的已有值，
  骨架屏不许自成一套配色。

首启还没有用户目录时，宿主注入的 `setup:true` 会让 `public/splash.js` 在 `<html>` 上落一个
`data-setup`，`index.html` 里那条 `html[data-setup] #splash { display: none; }` 把骨架整个
藏掉：那一屏该显示的是"选一个位置"，而不是先闪一张假的日历。文案仍从目录取（`setup.*` 那一组），
只是它由 React 画——骨架屏在这里没有活可干。

语言、主题、"是否首次启动"与"是否要选位置"由宿主（Rust）在建窗之前读
`<数据目录>\settings.json` 得出（目录不在就用默认值，**不为此建目录**），用
`initialization_script` 注入成 `window.__TAYME_SPLASH__`；`public/splash.js`
（本页唯一非 module 脚本）在首帧之前同步把它写进 `<html>`；注入缺失或脚本失败时退回
查询串（`?dt=minimal-dark`）与 `index.html` 的静态默认值（`zh-Hans` + `minimal-light`），
最坏是换装，不是白屏。在浏览器里跑 `npm run dev:web` 时没有宿主，走的就是查询串这条路。
注入的格式与 `src/shared/splash.ts` 的 `splashBootstrap()` 同源，由
`tests/splash-contract.test.ts` 核对 Rust 侧规则没跑偏（见 [architecture.md](architecture.md)）。

## 加一种语言

1. 在 `src/shared/ipc.ts` 的 `Locale` 联合与 `LOCALES` 里加成员；
2. 在 `messages/` 下照 `zh-Hans.ts` 建新目录；
3. 在 `messages/index.ts` 的 `CATALOGS` 里注册，并在 `localeNames` 里加自称；
4. `npm run typecheck` 会列出所有缺的键；
5. `npm test` 的键对齐断言会核对是否一一对应。

### 繁体中文要注意的

**不要写一个通用的简→繁映射表来转文案。** 一简对多繁在术语上一定会出错：
「历」在「万年历」里是「曆」，在「日历」里却是「歷」；复/復/複、发/發/髮同理。
逐条写。

`scripts/glossary/variants.mjs` 里那张异体字表**只做四库字形归一**（`徳`→`德`），
不是简繁转换器，别拿去转界面文案。

## 日期怎么办

`src/core/format.ts` 里的 `formatFullDate` / `weekDayLabel` 目前是简体模板，位于
core（纯逻辑层，不依赖 locale）。要支持多语言日期时，在此之上加一层渲染层的
`i18n/format.ts` 接受 locale，而不是把 locale 塞进 core——core 的边界是"不依赖界面"。

`src/core/date-key.ts` 的 `formatSolarDate()` 是第二个日期渲染器，它直接用引擎的
`toString()`，所以输出永远是引擎语言，不随界面语言变化。

## 语言与引擎的边界

`tyme4ts` **没有 locale API**（`getName()` / `toString()` 一律返回简体中文）。
`src/core/day.ts` 是引擎中文进入应用数据的唯一漏斗，因此：

- 界面文案（按钮、标题、设置项）由本层负责；
- 农历、节气、神煞、宜忌等**术语**不随本层变化，需要映射时在 `src/core/day.ts`
  那一层按词条显式处理，而不是猜一个转换规则。

这也是为什么 `Locale` 里没有英文：英文不只是翻译界面，还要为干支/神煞/二十八宿
发明一套词汇，而术语表当前的政策是**只写能引证的说法**（见 [glossary.md](glossary.md)）。
